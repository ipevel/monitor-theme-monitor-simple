# Monitor-Simple

简洁的 monitor 探针主题：总览条 + 状态筛选 + 亮暗切换。

[![ci](https://github.com/ipevel/monitor-theme-monitor-simple/actions/workflows/ci.yml/badge.svg)](https://github.com/ipevel/monitor-theme-monitor-simple/actions/workflows/ci.yml)

## 功能

**总览页**

- 总览条一格一个数：节点数 / **告警台数** / 最忙节点 / 本月流量 / 7 天内到期
  - 「告警」那格回答的是值班时第一个问题：有几台需要看。它和状态标签、卡片左侧的色条读同一个判定，所以数字、点开后的列表、卡上的标记不会互相矛盾
  - 告警格和到期格都可以点，直接筛出对应的节点
- 地区筛选（下拉）—— 直接读 API 的 `country` 字段，与卡片上的旗帜同源
- 状态筛选：告警 / 离线 / 即将到期 / 未接入（带台数）
- 排序：问题优先（默认）/ CPU 占用 / 内存占用 / 本月流量 / 到期时间
  - 「问题优先」把离线、数据不可读、超限、偏高、读数陈旧依次排在前面，健康节点沉底 —— 面板默认顺序是 hub 的序号时，一台离线机器可能躺在第三行中间
- 搜索名称或地区
- 网格 / 列表视图
- **网络质量**开关（默认关闭）：打开后每张卡多一行延迟与丢包，每分钟向各节点的历史接口取一次
- 筛选条件写进 URL（`?country=JP&status=离线&sort=cpu&q=…`），可以直接分享，刷新也不丢
- 节点卡：名称 + 国旗 + 状态，三个大数字（CPU / 内存 / 硬盘），一行脚注（本月流量 / 到期 / 流量重置）
  - 80% 转琥珀、92% 转红，低于阈值一律不着色；**告警时卡片左侧多一道色条**，四列白色卡片里一眼能扫到是哪几张
  - **负载与交换**另起一行：CPU 是两秒的窗口，一台 load 跑到核数二十倍的机器可能刚好落在调度间隙里读成 8%，而 swap 在被打爆时和正常机器长得一样 —— 两个数都在 payload 里，按同一套阈值着色
  - 陈旧读数不再冒充实时：agent 停止上报超过两分钟后，状态行写「数据陈旧 X 分钟」（琥珀点），数字转灰
  - 过期、即将到期、超流量、流量即将重置同样只在需要时着色
  - 离线或指标读不到的节点读数自动转为灰色，不冒充实时值
  - 脚注固定在卡片底部一行，左右两端对齐：流量重置文案长短不一，也不会把某张卡的脚注挤到第二行

**详情页**

- 页头有「← 返回列表」，向上滚动也一直在（详情是客户端路由，浏览器自己的返回键不一定在手边）
- 事实网格：系统 / CPU / 内存硬盘 / 架构 / 今日流量 / 负载与交换 / 续费
- `主机 / IP` 显示的是**这台机器被访问到的地址**，不是接口给的字段顺序：手工指定的优先，其次是网卡上的公网地址，网卡只有内网地址（NAT / 代理）时用 hub 看到的出口顶替，内网地址只在没有别的公网地址时才出现 —— 同一台机器在面板里怎么写，这里就怎么显示。鼠标停在地址上有来源说明（手动填写 / 网卡地址 / hub 看到的出口 / hub 看到的连接地址）
- 资源图表：CPU、内存、网络速率（带图例）、硬盘；尾部跟随实时推送
  - 四张图各自 memo：详情页挂在两秒一次的推送下，不隔一层边界的话每分钟要重排三四十次、每次最多 1500 个点
- 网络延迟：多探测线（逐条开关 + 削峰 + 丢包率）+ Brush 缩放
- 图表分块按需预取（`requestIdleCallback`），不再让所有访客都在首屏解析整个图表库

**实时性与状态**

- 页头指示数据来源：实时 / 轮询中 / 已断开
- WebSocket 6 秒没有消息即判定连接半开并主动重连；连线期间回落到 5 秒轮询
- 重连走指数退避（1 秒起，最长 30 秒）；标签页回到前台立刻拉取一次
- 每次推送逐字段比对，没有变化就沿用上一次的对象：一个安静的机群不该让排序、筛选和每张卡每秒重算两次
- 指标逐字段降级：缺一个字段只影响那一格，并且区分「刚连上还没上报」与「数据不可用」
- 分块加载失败会重载一次（主题就地更新后，旧页面手里的 chunk 已经不存在了），仍失败则给出可操作的错误界面，而不是白屏

**无障碍**

- 卡片是真正的链接，可以用新窗口打开、可以复制地址
- 从列表进详情时焦点落到标题（客户端路由不会自己播报），返回时回到进来的那张卡：记住的是它的地址而不是 DOM 节点 —— 详情在屏时列表已卸载，攥着旧节点去 `focus()` 是无效的
- 焦点环独立于配色：3px、不叠透明度，对白卡也有 4.8:1

**主题**

- 亮/暗切换，跟随系统，localStorage 记忆
- 首屏不闪：`.dark` 在 `<head>` 的内联脚本里挂上，不用等 React
- 配色只有一层含义：灰阶做骨架，饱和度留给「需要处理」的两档告警（`--warn` 80%、`--destructive` 92%）；选中态用中性填充，不用彩色 pill
- 所有小字对所在底色至少 4.5:1（含两档告警色本身），页底与卡片之间有明确明度差，四列卡片不会被看成一片
- 窄屏（375px）总览条折成两列网格，网格与列表两个视图都不横向溢出

## 与 hub 的版本关系

主题只读 hub 的公开接口（`/api/me`、`/api/nodes`、`/api/ws`、`/api/nodes/{id}/metrics`），
并且只做向后兼容的加法：字段在就用，不在就按老办法自己算。**hub v1.0.0 起都能跑** ——
hub 旧了不会报错，只是少一个更准的数。

| 字段 | hub 从 | 拿不到时主题怎么办 |
|---|---|---|
| `month_used` 本月计费流量 | v1.2.0 | 按 `traffic_mode` 从 `month_rx` / `month_tx` 自己算 |
| `ipv4_pin` / `ipv6_pin` 手工指定的地址 | v1.2.0 | 只用网卡地址与出口地址排序，忽略手工值 |
| `country` 取手工指定的国家 | v1.2.0 | 同一字段，旧 hub 给的本来就是自动查到的值，无需回退 |

`month_used` 在时以 hub 的为准：面板、流量告警和通知读的都是它，主题自己再算一遍，
迟早会和告警报出来的数不一样。

## 安装

把 `theme.tar.gz` 拖进面板「主题」页，或解压到 hub 的 `--themes` 位置：

```bash
mkdir -p /opt/monitor/data/themes/monitor-simple
tar xzf theme.tar.gz -C /opt/monitor/data/themes/monitor-simple
```

在后台「主题」页切换到 Monitor-Simple。

## 开发

```bash
npm ci
npm run dev        # 开发服务器，/api 代理到 127.0.0.1:9911
npm run lint
npm test
npm run build      # 构建到 dist/
```

`npm test` 钉住的是那些「改坏了界面不报错、只会画错」的地方：`src/lib/format.ts` 的刻度阶梯、`src/lib/series.ts` 的削峰、`src/lib/severity.ts` 的告警阈值、`src/lib/address.ts` 的地址取舍（错了会把一个机器根本不响应的地址当成它的地址）、`src/lib/node.ts` 的负载/交换判定、本月计费流量与陈旧判断（负载与交换那两条错了，一台被 swap 打爆的机器会安静地留在灰色里），以及 `src/assets/flags.ts` 那串国旗 sprite 的内部一致性。

## 分类说明

分类取 API 的 `country` 字段，匿名即可读到，因此筛选和卡片上的旗帜永远一致。

若想按「建站 / 入口集群 / ix 互联 / 落地服务器」这类**角色**分类，需要先有一个可解析的命名约定并写进这里 —— `remark` 匿名读不到，只凭节点名去猜，猜出来的分类和旗帜会分叉。

## 旗帜

卡片上的地区用国旗表示，旗帜来自 [country-flag-icons](https://github.com/UNITED-ELECTRONICS/country-flag-icons)（MIT），由 `scripts/build-flags.py` 生成成一份内联 sprite（`src/assets/flags.ts`，**253 面**，163 KB，gzip 后 44 KB —— 主 chunk gzip 后 144 KB 里有 44 KB 是它）。

- **为什么不直接用 emoji**：Windows 的 Segoe UI Emoji 没有国旗字形，`🇯🇵` 在 Windows 上只会渲染成「JP」两个字母，等于没换。
- **为什么内联而不是放文件**：hub 决定 `Content-Type`，SVG 只要不是 `image/svg+xml` 就进不了 `<img>`；内联的 sprite 既不会 404，也不依赖 hub 的 MIME 判断，还省掉每个国家一次请求。
- **为什么不用 flag-icons**：那个包把纹章一笔一笔画出来（西班牙 91 KB、塞尔维亚 184 KB，全套 1.1 MB）。卡片上旗帜只有 20×13 px，这些路径全是亚像素 —— 同样的西班牙国旗在 country-flag-icons 里是 599 字节。
- **sprite 覆盖源目录里的全部 ISO 3166-1 alpha-2 旗帜**，不是一份手写清单：hub 存的国家码是从 IP 查出来的标准两字母码（`ISO 3166-1 alpha-2, uppercase`），任何一个都可能出现。只排除 `TW`（中国台湾没有地区旗）与 `XA` / `XC` / `XO`（源里的占位图，不是国家码）；源里另有 `GB-ENG`、`ES-CT`、`BQ-SA` 这类下级区划，按「两字母」过滤掉 —— hub 的国家码永远只有两位。
- 表里没有的代码走同一条回退路径：卡片上仍是字母徽章，不会出现空一格。**而这正是 CN / GB 等 133 面旗缺席两个版本没被发现的原因** —— 缺一面旗是回退，不是报错，所以 `build-flags.py` 现在直接枚举源目录，并在数量不足时拒绝写出 sprite。

换了旗帜来源或增删代码时重新生成：

```bash
npm pack country-flag-icons@1.6.20 && tar xzf country-flag-icons-1.6.20.tgz
python scripts/build-flags.py package/3x2 src/assets/flags.ts
```

## 主题包

`theme.tar.gz` 包含 `dist/`、`theme.json`（以及存在时的 `preview.png`），即 hub 可安装的主题目录格式。

发布时打一个 `v*` tag，CI 会跑 lint / test / build、校验 `theme.json` 的 version 与 tag 一致，再把包和 sha256 挂到 Release 上。

面板上那张卡显示的是**主题包内 `theme.json` 的 `description`**，而且面板只在「远端最新 release 的 tag ≠ 已装版本」时才重新下载 —— 改简介必须同时升版本号。
